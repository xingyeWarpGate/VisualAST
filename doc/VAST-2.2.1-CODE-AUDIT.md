# VAST 2.2.1 code audit

Audit date: 2026-08-29

## Verdict

The repository has a working 2.2.1-shaped structural pipeline, but it does not yet satisfy the full execution specification. The honest conformance level remains `STRUCTURAL`.

## Requirement matrix

| Area | Status | Evidence | Gap |
|---|---|---|---|
| Versioned cross-module models | Partial | `SemanticProposal`, `CanonicalSceneContract`, `AestheticPlan`, `RenderIntent221` and Zod schemas exist | Not every application boundary invokes the versioned schema parser before accepting data |
| Semantic Runtime | Partial | Typed operations, provenance, ambiguity fields, deterministic parser and synonym/metamorphic checks exist | The fallback parser is lexical rather than general semantic parsing; causal events, emotions and open meaning remain shallow |
| Deterministic Constraint Core | Partial | Proposal, entity, presence, identity target, relation participant, event participant, count and openness validation exist | Scale tolerance, composition dependency, narrative prop lock, scene identity lock and source-authority override checks are incomplete |
| Aesthetic Planner | Partial | Focal hierarchy, composition, pose/physics, lighting, face identity, information budget, credibility and freedom outputs exist | Passes are not independently testable; external policy profiles and visual ablation proof are missing |
| Complexity and staging | Partial | Attention budget, gate and four-stage plan exist | `image-cli` has no mask/staging capability, so local-lock guarantees cannot be proven |
| Compiler | Partial | Ten named passes, compression audit, hard/soft items and renderer-neutral output exist | Passes are labels inside one function, not isolated deterministic pass modules; compression audit is mostly declarative |
| Renderer adapters | Partial | `mock`, `image-cli`, registry, JSON validation, redaction and file existence checks exist | Local Hermes OAuth is unavailable; project adapter has not produced a successful real image |

| CLI | Mostly implemented | parse, validate, plan, compile, render, evaluate, revise, inspect, test and doctor routes exist | `doctor` and suite selection are not yet comprehensive enough for all specification gates |
| Semantic/metamorphic tests | Partial | Local deterministic checks and nine compatibility regressions pass | Tests are small and do not reach the specified pass-rate corpus |
| Holdout tests | Missing | Report explicitly says `NOT_RUN` | No external holdout corpus |

| Aesthetic ablation | Missing | Variants are listed | No visual metric proves the full planner is better |
| Live-render suite | External comparison only | Five readable images were generated with Codex built-in authorization and manually reviewed | They were not generated by `image-cli` from the exact `RenderIntent`; they do not qualify for `CLOSED_LOOP_CONFORMANT` |
| Evidence bundle | Partial | Required artifact names and run records exist | Several metrics were previously hard-coded and must be derived from executed suites before final completion |

## Five-case findings

The five random cases successfully exercised the webpage and image inspection path. During SSE testing, the compiler was found to emit forbidden entities in positive mappings. This was fixed by filtering forbidden presence nodes from focal hierarchy, shape rules, attention counts and entity mappings.

The tests also exposed Runtime extraction limitations. Generic Chinese entity, count, style, framing and forbidden-list handling were expanded, but a model-backed schema-constrained Runtime is still needed for broad-domain semantic coverage.

## Completion blockers

1. A successful authenticated `image-cli` run using the exact compiled prompt.
2. At least six live images and two real revise/render loops.
3. A visual Evaluator with observable region evidence and typed patches.
4. External holdout cases and measured semantic/metamorphic pass rates.
5. Visual ablation proving Planner effectiveness.
6. A complete unit suite run whose result is captured rather than assumed.
